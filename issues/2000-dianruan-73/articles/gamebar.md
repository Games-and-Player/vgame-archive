## 超级机器人大战α（スーパーロボット大戦α）（PDF p.77）

机种 PS　厂商 BANPRESTO　类型 S·RPG　媒体 CD-ROM

一直以为BANPRESTO和ENIX没什么关系，其实它们也的确没什么太大的联系，但看到两家厂商赏且且声都会在1999年12月发售的各自招牌的最新作却同时从12月延期到今年3月，又从3月一起延至到5月，不久在网上又出现了都再延到8月的传闻，那就难免会让人怀疑不是阿姆罗想去屠龙就是史来姆要驾驶高达了。还好，SRWα终于在5月25日如期发售了。

战斗动画总算可以关掉了，实在是令人无比欣慰。随着开关动画能省去大量重复的镜头和大量读盘的时间从而大大缩短每一场战斗的耗时，同时也使战斗的节奏更为紧凑。不过BANPRESTO并没有因为可以关掉战斗动画而偷懒，全配音自是不提，战斗动画中机体的动作非常的流畅与自然，封套上自称都是full animation，虽有王变实尖之嫌却也并非虚妄之词。

系统上还是老样子，故事倒是有点奇怪，好像和前几作无关无联，又从第二次的基本没定开始重新演绎，与其称之为α，不如叫ZERO更合适一点（当然也许α在希腊文原义中就包含着最初和开始之类的意思，只是对我们而言ZERO要清楚明白得多）。故事是又要的，无论怎样的剧情组织，只要能让我们使用众多英雄来和同样众多的著名或即将著名的敌人作战就足够了。

总觉得SRWα是一部很精致的作品，不仅仅是因为漂亮的战斗动画和完整的原作剧情，系统上一些录巧的设计、卡拉OK模式中丰富的选曲（不过没有画面画面是无聊），以及不少小节上的注意，比如跑路和万能长都可分离，V高达扔出跟部的攻击方式，而CG虽然画面比较小但看得出都重新做过了，质量也不错，其他如完成机体改造工作进入下一版时会随机出现一张精美的CG插图等等都体会得到制作者的用心。

SRWα牺有超过迄今为止一切SRW游戏的实力，而DC上的α又会是怎样的呢。

## 水痕之书（THE BOOK OF WATERMARKS）（PDF p.77）

机种 PS　厂商 SCEI　类型 AVG　容量 CD-ROM×2

买它，纯粹是因为 + r1 + 是SCEI的作品。对于SCEI的信赖本人由来已久。如果说SCEI的制作水准是堪有几家能做到的话，我觉对相信。这款 + r1 + 也算得上是同类作品中出类拔萃的了。

本作给人的最大感觉，倒像是 + r1 + 的新作。同样以 + r1 + 为线索，同样在 + r1 + 上探索，真是越玩越疑惑。以前提到 + r1 + 时，曾指出此类作品的特点。CG，本作中发挥的要比其它作品略强一些（纯属个人意见）。迷题方面虽然有点过于难为人了。也许有些IQ最高的者者会觉得容易吧，但是故意为被解谜作品昏得得病的人来说，实在是只能是苦中做乐。有时真是一种自己给自己找罪受的感觉！所以，笔者在玩至一半的时候便收手去练 + r1 + 了。

还是那话，如果你真对解谜有足够的自信的话，就请试试看，SCEI所营造出的感觉颇为独特！

## TO HEART（PDF p.78）

机种 PS　厂商 AQUAPLUS　类型 SLG　媒体 CD-ROM×2

自从 + r1 + 大获成功以来，无论是纯恋爱游戏还是带有恋爱要素的其它形式的游戏都层出不穷。但是正统的学园恋爱游戏却比较少见了，而 + r1 + 恰恰很好地弥补了这个空缺。

和 + r1 + 、 + r1 + 及 + r1 + 等游戏不同， + r1 + 不是以周为单位来安排学习，而是以日为单位，从每天的日常着手（也就是说更接近于心跳前期场）。我个人认为这种结构更适合恋爱题材的游戏，它能对人物进行非常细致的刻划，从而令玩家更加投入，同时也更为真实。本来嘛，恋爱就是在日常生活中一点一滴积累起来的，而那和每周进行单纯的数值上升训练，在周日规则是例行的约会。如果约会不是在特定事件就这些以前曾相识的话，做一些似曾相识的选择，女孩们再似曾相识地予以反应，然后好感上升，然后就更为遥远了。过了程式化的操作使女孩变得像娃娃，感觉也更为遥远。神岸あかり对我而言与比那膝跑这更要求更有吸引力，尽管她也没有后者那么完美。

 + r1 + 有一些很有趣的细节，如每周六可以收听牛顿岛美音子主持的HEART TO HEART的广播节目，而三个小游戏也做的不错十分真。在最近几期杂志的日本家用游戏排行榜上还看得到 + r1 + 的名字，我想写它的OVA发美也有不少关系吧。话说回来，它的OVA的确不错，喜欢 + r1 + 的朋友大可去看一下。

## 牧场物语2（牧場物語2）（PDF p.78）

机种 GB　厂商 VICTOR　类型 SLG　媒体 卡带

对于这种经营类的游戏我向来不太 + r1 + ，在朋友的强烈推荐下，我才拿了购买了本作。

经营模拟的游戏在已只有前半部分好玩。比如《三》，一旦过了最初的困难时期，建立起自己的势力，游戏也就开始变的乏味了。再比如PC上很热的《模拟城市》系列，初期规划得好以后玩家就可以去睡午觉了。入口和金钱会自动增长的……相比之下，经营一个牧场反而更需要玩家的参予了。你必须抓紧时间，灌溉田地，喂养禽畜，到收获的时候，还真有龙口夺粮的紧张。这是一个相当代表的游戏，因为玩家只有游戏中的三年时间来经营牧场，而且时间是自动流逝的。也许这种设定是让整个游戏显得过于紧凑，有些小品的味道，不过这也是吸引玩家的一种方法，至少比那些无法令玩家投入的游戏要好。

如果要指出游戏的不足，那么上手困难应是最主要的一个！甚至于打穿一遍以后都不敢说全掌握了游戏方法，就像真正的农耕一样，要在实践中积累经验，不断提高工作效率。

## 最终幻想·策略版（FINAL FANTASY TACTICS）（PDF p.78）

机种 PS　厂商 SQUARE　类型 S·RPG　媒体 CD-ROM

首先想提一个常识性的问题：游戏史唯一的一款百万级SLG是什么？PS迷或者喜欢SQUARE的玩家大概都知道吧，就是这款在97年推出的FFT。

恰好在FFT发售三周年的时候，笔者又拉起了这款老游戏，而且其投入度绝不逊于近期的任何新作，对于数量多得有些泛滥的PS游戏来说，这多少有点不可思议啊！虽然是97年发售的游戏，但其经典的设定仍不逊于现在任何一部大作游戏。

正如制作人松野泰己敢于在FF后面加上字母 + r1 + 的信心所代表的，这是一款敢于把自身的战略性和FF的名气相提并论的游戏。虽然有人会说FFT的系统不过是脱胎于 + r1 + （它也就是大名鼎鼎的 + r1 + ）而已，但在SFC的新盛时期， + r1 + 也差能在销量上为后起的FFT树立一座高不可攀的山峰，而那时SFC的普及量远高于尚在青年期的PS。这不能不说明FFT确实在某些万面拥有超越前辈的实力。

特点——慢。但是笔者在游戏中并未感到拖延，反而觉得异常充实。因为FFT + r1 + 在AI的思考过程，这也正是其出众之处。相比之下，同时期的 + r1 + 就要失败得多——认为S·RPG就要把视觉效果弄得和RPG一样出色，本身就是一个误区。

而FF风格与松野泰己风格相互融合产生的世界观，更是为本来就出色的前台演出村上了一块同样出色的背景幕布。FF的转职、魔晶石、陆行鸟，再加上松野泰已崇尚的西欧骑士精神，这都令玩家仿佛置身于一个既现实又虚幻、既亲切又遥远的世界中。

与丰富系统和逼真世界观相比，固定的16人队伍有些显得有些刻薄了。一会儿是人手不够，一会儿又队伍超编；一边是自己培养的能力较强的闲兵，一边是固定加入的角色，经常会让人感觉难以取舍。

最后想说的本人一个小发现，不知大家对女性拳法家（モンク）的头像还有没有印象。仔细看看，是不是很像另一款游戏中的人物呢（脸型＆发型＆表情）？

## PS2软件开发困难问题之我见（PDF p.79）

文/上海　小文

PS2发售已经将近四个月了，无论有没有购买，相信大家都或多或少的看到了一些PS2的游戏画面。可能有些人对PS2的游戏画面觉得非常震撼，但也可能有人对于PS2的画面素质表示失望。的确，性能数据比上代DC强那么多，为什么画面却没能表现出期望中的那种差距呢？说得没错，现在的PS2游戏看起来未必比DC好多少，多边形数目也没有多少优势，难道SONY在骗人？呵呵，不是啊，原因其实很简单，就是因为PS2的游戏开发难度高！说说简单，但到底开发工作难在哪里？以后又是否有可能改善和提高呢？

### GPU的强大令传统的开发观念受阻

由于PS2的硬件设计的因素，程序员们发现对PS2的编程方式有点特别。传统的编程方式是以CPU为中心，任何要显示到屏幕的东西都是经过一道逻辑处理然后交给CPU，CPU处理完后交给GPU这样主流程的设计思想，相对较单纯，流程也比较容易掌控。可以看出，CPU几乎要逐个完成所有的前期处理。这在以前是没有什么问题的，但随着GPU的能力越来越强，T&L（Transform and Lighting，多边形变换与光源处理）都可以由GPU硬件来独立完成了，这种完全以CPU为中心的处理方式就体现出了其不足之处。要知道，对于一个处理器来说，只要操作系统没有给它 + r1 + ，它就会一直处在无效的循环中，而这就将造成机能的浪费，也就是目前PS2程序员所面对的最大问题。如果想把PS2的能力发挥出来，就必须依据很多处理器合起来的思路来编程。但目前的状况是，许多程序员还停留在传统的编程概念上，造成了机能的浪费！相信估算，传统方式至少浪费了50%的机能！。所谓PS2软件开发难，也就是难在怎么样才能做到最好的协调问题，让所有的处理器都能充分发挥其能力。

### 库函数不足

目前PS2的开发环境确实和以前的PS有一些不同，PS2并未象PS那样提供比较完整的库函数，而是只提供其基本的SDK，同时将所有的硬件细节全部公开。据猜测，这可能是出于市场的问题，PS2推出的时间紧凑，SONY没能做好完善的库函数，只有先发售主机，而后再将库函数慢慢完善（现在看来确实是这样！）。那么，对于程序员来说，就不是面对于库函数而是要直接面对开放的硬件环境，这样的情形就造成了3个问题——必须了解硬件、通晓汇编才能开发出更好的软件，但一般的TV-GAME软件程序员多是使用高级语言或者习惯于直接调用厂商提供的库函数，很少会用汇编，因此PS2软件自然就没有那么得心应手了。

### 开发形式让小厂商们望而生畏

上文说过，以前SONY为PS的软件开发人员提供了相当完善的库函数，但这次PS2的开发人员只得到了基本的SDK。这种做法所造成的弊端显而易见——对于软件商的初期开发来说要求太高端，力量强的小厂商会对PS2蓋而生怕。想要诞生出高素质的PS2游戏，厂商就必须有足够的能力开发出自己的、更好的库函数。但开发库函数可赚不了钱（拿出去卖另当别说！），大厂商自然有能力，可按技术力薄弱的小厂商就只能开发出象 + r1 + 这种的游戏了。

### 缺乏除错软件是开发优秀软件的绊脚石

据说，至少在4月上旬，各PS2游戏开发商手中还是没有得到开发用DEBUG软件。也就是说，现在大家所看到的PS2游戏几乎都是在没有除错功能的环境下制作出来的。写过程序的人一定知道，面对一个没有DEBUG功能的环境进行除错工作是一件多么痛苦的事情。这样自然就造成了PS2软件开发周期变长、成本上升的弊端。另一方面，由于没有DEBUG软件，为了避免日后除错时的麻烦，程序员宁可默默守陈规，也不愿尝试新思路，这样也抑制了程序员的发挥。

### 开发环境将逐步完善，未来值得期待

综上所述，可以预见现在PS2尚在早期阶段，由于开发环境不完善，缺乏足够的程序库，大多数小厂商都会很难爬过PS2这个高门槛。即使勉强开发出了游戏，画面表现上也必然中庸。但随着PS2开发环境的逐步完善，这种现象就会有所改变。首先，SONY现在已经在全力开发更多更好的库函数（各PS2开发商纷纷叫唤PS2难以开发就是对SONY施加压力，希望SCE能够提供更多的库函数，以减省开发费用——现在看来这种做法确实很有效 + r1 + ）其次，各厂商的底层开发的库函数的好处就会体现出来。自己开发的库函数在编程中会更加直接，库的修改和升级也会合乎便利。只要度过了初期的底层开发阶段，以后的开发就越来越趁手心应手，也就会创造出更多的奇迹。第三，开发程度高了，市场上也会慢慢出现越来越多的中间件可以购买，这样就为技术力不足的小厂商提供了机会。

其实，在PS中后期也有很多厂商不再使用SONY所提供的那套东西了。大家可以把自己手上的PS光盘放到电脑里浏览一下，TIM（图形文件）、STR（动画文件）、XA（音乐音效文件）等文件都是用SONY所提供的生成工具做的所谓标准文件，此外还有许多游戏都没有使用这些标准文件，特别是一些大牌厂商的大作。这并不是因为他们不守规矩自找目力，而是与家用机的表现比起来有相对较大关系。硬件平台是固定的，要做完美的画面，就必须尽可能地榨干硬件资源，而依靠SONY所提供的开发工具又无法满足自己的要求，因此只能自己创新。

另外，SONY也一直在进行PS2开发环境的改善，根据SONY公布的时间表，SCEI已决定将在年内提供大量新的程序库。6月将提供VEC-TOR UNIT用的程序库和多种范例程序，同时包括诸代码。在修整多边形和顶点计算等程序的处理时，PS2的画面将更上一层楼，实现毫秒1000万以上的多边形运算；8月将提供通讯用程序库，一种是为网络所设计的TCP/IP通讯协议程序库，另一种是为了扩张设备所准备的程序库，还会有与手机连接所需要的程序库，届时PS2也将可以和手机连接；9月还会有新的绘图程序库登场。除了新的程序库外，SCEI也决定提供一些新的开发工具，比如音效的编写工具等。那么对于玩家而言会有怎样的意义呢？很简单，就是我们以后能够更快地看到真正体现PS2实力的游戏！我们相信，在不远的将来一定会在PS2上诞生出令人震惊的飞跃之作！
